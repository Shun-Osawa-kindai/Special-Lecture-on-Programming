背景オブジェクト「木」のコード移植

背景オブジェクトである「木」の描画コードをプロジェクトに組み込みます。

  • プロジェクト側にはすでに treePos_x や treePos_y といった位置変数が用意されています。
  • これらを基準点として、木の各パーツ（幹・葉）を相対位置（オフセット計算）で配置し直す必要があります。
function drawTree() {
  fill(120, 80, 40);
  rect(treePos_x, treePos_y, 30, 150);
}

Coordinate Math

Offset Arithmetic

基準点からの差分（オフセット）の計算：X軸

① 絶対座標から相対座標への変換

元の絶対座標（例: 850）と基準点（例: 900）の差分（900 - 850 = 50）を求めます。
treePos_x - 50 のように書き換えることで、基準点が動いたときに木全体が連動して移動するようになります。

② トライアングル（葉）のX座標例

// 1つ目の三角形の頂点
triangle(
  treePos_x - 50,
  treePos_y,
  ...
);
Game Project Integration Slide 5 / 10
Y-Coordinate Math

Vertical Offsets

基準点からの縦方向の差分計算

X座標と同様に、Y座標についても基準点（treePos_y）からの高低差を計算します。

  • 基準点より上にあるパーツ：treePos_y - 50 のように引き算
  • 基準点より下にあるパーツ：treePos_y + 50 のように足し算
triangle(
  treePos_x - 50, treePos_y + 50,
  treePos_x + 30, treePos_y - 50,
  treePos_x + 110, treePos_y + 50
);

Debugging Practice

Troubleshooting

画面が真っ白になったときのデバッグ手法

よくあるエラー例

複数が入り組む座標計算では、変数名のタイポ（例: treePos_x を treepos_x と大文字小文字を間違える等）が発生しやすくなります。

ReferenceError: treePos_x is not defined

解決のための3ステップ

  • 1. コンソールを確認： 赤文字のエラーメッセージと行番号を見る
  • 2. スペルチェック： 変数名や関数名（triangle 等）の綴りを確認
  • 3. 一時的なコメントアウト： 怪しい行を順にコメントアウトして原因箇所を絞り込む

Trial & Error

Iterative Process

試行錯誤はプログラミングの正常なプロセス

複雑な座標計算を一度で完璧に書き上げるプログラマーはいません。

実行結果を見て「形がおかしい」「表示されない」ときは、ひとつずつ数値を調整し直します。失敗を恐れず、修正を繰り返すことで正確なコードに仕上がります。

安全な修正のコツ

  • 古いコードを完全に消さず、コメントアウトして残しておく
  • 新しい書き方を試して比較する
  • 一箇所ずつ確実に動くことを確かめる

Tree Completion

Multiple Parts

複数のパーツを連動させる

function drawTree() {
  fill(120, 80, 40);
  rect(treePos_x - 15, treePos_y - 150, 30, 150);
  fill(0, 150, 0);
  triangle(treePos_x - 50, treePos_y - 100, ...);
}

幹と複数の葉（三角形）のすべての座標が treePos_x と treePos_y を基準とした相対計算に置き換わりました。

これにより、変数 treePos_x の数値を書き換えるだけで、木全体がシーン内の好きな位置へスムーズに移動できるようになります。
