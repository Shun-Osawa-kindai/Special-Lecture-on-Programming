Data Structuring

From Individual Variables to Objects

変数が増えたら
「オブジェクト」で構造化する

個別の変数が乱立する問題

木の描写のために treePos_x, treeTrunkHeight, treeTrunkWidth, treeRadius といった大量の変数を作ると管理が大変になります。

変数名の先頭に同じ単語（tree...）が繰り返し登場するのは、構造化のシグナルです。

オブジェクトによる1つの「塊」への集約

対象となる1つの要素（エンティティ）に関連する変数を、1つの「オブジェクト」としてまとめます。

コードが圧倒的に読みやすく整理され、管理や修正が一元化されます。

Declaration & Properties

オブジェクトの記法とプロパティ定義

  • 宣言 (Declaration): 変数同様に var tree; で宣言します。
  • 波カッコ {}: setup() 内で tree = { ... }; のように定義します。
  • コロン :: プロパティ名と初期値を : で結びます。
  • カンマ ,: 各要素の末尾を , で区切ります。※最後の要素の直後にはカンマをつけない約束です。
木のオブジェクト定義
var tree;

function setup() {
  tree = {
    pos_x: 256,
    trunkHeight: 150,
    trunkWidth: 30,
    radius: 60 // 最後の要素はカンマなし
  };
}

Access & Refactoring

Dot Notation & Tools

ドット記法（.）と安全な一括置換

ドット記法での呼び出し
// ドット記法でオブジェクトのプロパティを渡す
ellipse(tree.pos_x, 300, tree.radius, tree.radius);

rect(tree.pos_x, 300, tree.trunkWidth, tree.trunkHeight);

ドット記法 (Dot Notation)

tree.pos_x のように、オブジェクト名.プロパティ名 で値を取り出します。入力中にドットを入れるとエディタの補完候補が表示されます。

検索・置換（Find & Replace）を活用

手動で打ち直すのではなく、エディタの置換機能（treePos_x ➔ tree.pos_x）で安全かつ確実にリファクタリングしましょう。

Best Practices

Rule of Thumb

オブジェクト化を見極める2つのサイン

サイン1：単一のエンティティを描写している

独立した1つの対象（木、ロケット、プレイヤー、雲など）を形作るために複数の変数が使われている場合、それらは1つのオブジェクトにまとめるべきです。

サイン2：同じ単語が先頭に繰り返し使われている

treeX, treeY, treeSize のように変数名の先頭に同じ言葉がつく場合、それはオブジェクト化の確実なサインです。

アンチパターン（NG例）：「木」と「雲」のように異なる要素の変数を1つのオブジェクトに混ぜてはいけません。1つのオブジェクトには1つの対象の属性だけを集めましょう。

Summary

Clean & Scalable Code

オブジェクトがもたらす高い保守性

オブジェクトを使うことで、ばらばらだった変数が意味のある構造へと進化しました。

オブジェクト導入のメリット

  • 古い個別変数の宣言（var treePos_x...）を削除でき、コードが大幅にスリム化
  • tree.pos_x = 300; のように1箇所の数値を打ち替えるだけで全体が綺麗に更新
  • 今後登場する複雑なアニメーションやゲームのデータ管理に必須の基礎スキル

「関連するデータを1つにまとめる。それが良い構造化の第一歩」
