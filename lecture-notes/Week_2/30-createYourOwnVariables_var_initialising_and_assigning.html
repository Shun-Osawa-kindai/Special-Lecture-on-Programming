Adaptable Drawings

Hardcoding vs Variables

直値指定の限界と変数の必要性

直値指定（ハードコーディング）の問題点

太陽のように独立した1つの円なら、Y座標の数値を打ち替えるだけで移動できます。

しかし、「幹」と「葉」からなる木や、「複数の円」でできた雲のように、複数のパーツで作られたオブジェクトは、1つの座標だけを変えると形が崩れてしまいます。

自作変数によるアプローチ

オブジェクト全体の「基準位置」を保持する変数を1つ作成します。

変数値を1箇所打ち替えるだけで、すべての構成パーツが連動して移動する柔軟なコードへと進化させます。

Variable Lifecycle

Three Steps

変数の3ステップ：宣言・初期化・使用

  • 1. 宣言 (Declare): スケッチの最上部（グローバル領域）で var treePos_x; を宣言します。
  • 2. 初期化 (Initialize): setup() 内で treePos_x = 156; と初期値を代入します。
  • 3. 使用 (Use): 描画関数の中で数値の代わりに treePos_x を渡します。
自動補完（Code Completion）: エディタで変数名を入力し始めると候補が表示されます。タイピングミスを防ぐため積極的に利用しましょう。
木の座標の変数化
var treePos_x; // 1. 宣言

function setup() {
  treePos_x = 156; // 2. 初期化
}

ellipse(treePos_x, 300, 60, 60); // 3. 使用

Relative Positioning

Offset Arithmetic

基準位置 ＋ オフセット（算術演算）

雲のように3つの円で構成される図形の場合、各パーツの絶対座標を「基準点 ＋ 離れた距離（オフセット）」に分割します。

オフセット計算による雲の移動
// 中央の円（基準点）
ellipse(cloudPos_x, 100, 50, 50);

// 右側の円（基準点 + 30px）
ellipse(cloudPos_x + 30, 100, 50, 50);

// 端の円（基準点 + 50px）
ellipse(cloudPos_x + 50, 100, 50, 50);

相対関係を保ったまま一括移動

関数の引数の中で + や - の加減算を行います。
cloudPos_x の値を打ち替えるだけで、3つの円が位置関係を保ったまま一斉に移動します。

Scaling & Formatting

Multiplication & Clean Code

拡大縮小（スケーリング）とコードの整理整頓

乗算（*）によるスケーリング

変数 cloudScale = 0.7; を作成し、図形のサイズやオフセット距離に掛け合わせます。

ellipse(
  cloudPos_x + 30 * cloudScale,
  100,
  50 * cloudScale,
  50 * cloudScale
);

コードの改行と可読性向上

引数内に計算式が増えて長くなった時は、コンマの後に改行を入れましょう。

  • 関数の引数ごとに改行することで、視認性が大幅に向上します。
  • 各行にコメント（// X位置）を添えることで、あとから見直す際の迷いを減らせます。

Summary & Challenge

Endless Possibilities

変数化がもたらす表現の拡張

変数を導入したことで、「1つの描画処理」から「大きさや位置が異なる無限のパーツ」を生み出す準備が整いました。

アレンジチャレンジのアイデア

  • 太陽に放射状の光線（line）を追加し、太陽のY位置と連動させる
  • サイズの異なる複数の雲をキャンバス上に浮かべてみる
  • 異なるサイズや位置の木々を追加し、奥行きのある風景を作る
