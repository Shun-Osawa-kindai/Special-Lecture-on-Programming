Foundations of Algorithms

なぜアルゴリズムが必要なのか？
「計算機が解くべき問題の定義」

アルゴリズムを学ぶ前に、まず「なぜアルゴリズムが必要なのか」を問う必要があります。

アルゴリズムの唯一の存在理由は「問題を解くこと（Solving Problems）」です。

では、計算機科学において「問題（Problem）」とは一体何を指すのでしょうか？

What is a Problem
Mathematical Translation

Context and Mathematics

日常の疑問を「数学の言葉」に翻訳する

Q1

計算機が答えられない問い

「私は休暇を取るべきか？（Should I take a holiday?）」

文脈のない問いに計算機は答えられません。答が「Yes」だと人間同士には自明でも、感情や感覚を直接処理することはできないからです。

Q2

計算機が解ける問い

数値（Number）や真偽値（True/False）への変換。

プログラミング言語の種類に関係なく、根本となる表現は必ず厳密な数学的データでなければなりません。

Example Formulation

Holiday Allowance Problem

問いの数理モデル化：x > y

「休暇を取れるか？」という問いを、整数の変数を使って厳密に定義します。

  • 年間付与日数： 整数 x 日
  • 取得済み日数： 整数 y 日
  • 数学的な問い： x > y は真か？
  • 出力（Output）： true または false

Desired Output

Designing the Answer

「どんな形の答えが欲しいか」を決める

出力形式 A：真偽値（判定のみ）

true または false

「取れるかどうか」は分かりますが、具体的な旅行計画を立てるには情報が足りません。

出力形式 B：残り日数（有益な数値）

x - y （残日数そのもの）

差が正なら休暇可能であり、かつ「あと何日取れるか」まで分かります。求める出力の定義が問題の価値を決めます。

Problem Definition

Core Formalism

計算科学における「問題」の構成要素

1. 明確に定義された入力（Well-defined Input）

対象となるデータ集合（例：整数 x, y）。

2. 明確に定義された出力（Well-defined Output）

期待される解答の形式（例：残日数を示す整数、真偽値）。

3. 入力に対する問い（A Question about the Input）

入力を受け取り、対応する出力を確定させる数理的な要件。

Problem Definition
Case Study

Integer Solution Problem

if x² = 2 ならば、x は integer（整数）か？

この問題の入力と出力は何でしょうか？

  • 入力（Input）： 方程式全体ではなく、数値 2
  • 問い（Question）： if x² = 2 のとき、x が integer（整数）か否か
  • 出力（Output）： true または false
Case Study
Multiple Approaches

Two Ways to Solve

同じ問題に対する「2つの解法」

解法 1：直接計算アプローチ

√2 を直接算出し、それが整数かどうか判定する。

注意：平方根の算出自体は基本演算（加減乗除）に含まれないため、追加の手続きが必要。

解法 2：探索的列挙アプローチ

1² = 1, 2² = 4 と順に自乗を計算し、2 を超えた瞬間に打ち切る。

特徴：基本乗算と大小比較だけで今すぐ完全に実行可能。

Algorithm Definition

Step-by-Step Instructions

アルゴリズムとは何か？

アルゴリズムとは、従うことで問題を解決できる「一般的で単純な一連の手順（命令列）」です。

要件 1：正当性（Correctness）

導き出される出力が、問題に対する正しい解答であること。

要件 2：基本命令のステップ

基本的な算術演算（加減乗除）や論理判定（if-then）の組み合わせで記述できること。

Generalization

Scaling the Input

問題の拡張：if x² = 1601 ならば、x は integer（整数）か？

対象が 2 から 1601、さらに任意の整数 y へ変わったとき、if x² = y, is x an integer? という問いに対する解法はどうなるでしょうか？

  • 平方根法： √1601 の汎用計算アルゴリズムが必要
  • 列挙法： 1から順に二乗を試す（計算ステップ数が膨大になる）
  • どちらがより良い解法か？ これこそが本モジュールの中心命題です。
