Memory Constraint

コンピュータは有限の情報しか保存できない

現実のコンピュータには有限量のメモリしかありません。

したがって、コンピュータが直接扱えるデータも、有限の長さで表現できることが前提になります。

Integers

2.1 Integers

整数は有限桁で表現できる（ただし上限はある）

任意の特定の整数は、有限桁で表現できます。例えば 12345 は2進数に変換しても有限桁です。

ただし、これは「一台の固定されたコンピュータが、どれほど大きな整数でも保存できる」という意味ではありません。

コンピュータのメモリは有限なので、保存できる整数の大きさには上限があります。

ここで重要なのは：

一つひとつの整数は、原理的には有限の記号列として表せる

Rational Numbers

2.2 Rational Numbers

有理数は「2つの整数」として正確に保存できる

有理数とは、2つの整数 p, q を使って p / q（q ≠ 0）と表せる数です。

例えば 1/3、17/12、-5/2 などです。

分子と分母をそれぞれ整数として保存すれば、有理数を正確に表現できます。

例：1/3 の保存
numerator   = 1
denominator = 3

→ 「小数展開」ではなく「整数ペア」で保持する

Rational Storage
Practical Caveat

Floating-Point Caution

実際のコンピュータでは少し注意が必要

通常の浮動小数点数では、有理数であっても正確に保存できないことがあります。

例えば10進数の 0.1 = 1/10 は、2進数では有限桁で終わりません。

そのため一般的なプログラミング言語では、0.1 は内部的には非常に近い別の数として保存されます。

  • 分数 (p, q) として保存： 正確
  • 浮動小数点数として保存： 近似になることがある
Decimal vs Binary 0.1 = 1⁄10 0.0001100110011...2 finite decimal, infinite binary expansion

Irrational Numbers

3. Irrational Numbers

無理数は有限桁では正確に保存できない

無理数とは、整数 p, q を使って p / q（q ≠ 0）という形に表せない実数です。

代表例は √2、π、e です。

例えば円周率は π = 3.14159265358979323846... と無限に続き、途中で終わることも、一定のパターンを繰り返すこともありません。

したがって、π のすべての桁を有限メモリに数値として保存することはできません。

Examples √2,   π,   e not representable as p / q
Irrational Numbers
Transcendence of π

3.1 Transcendence

π が超越数であるとは

講義では、π は無理数であるだけでなく、超越数であることにも触れます。

√2 は無理数ですが、x2 - 2 = 0 という整数係数の方程式の解です。このような数を代数的数と呼びます。

一方、π はどのような整数係数の多項式の解にもなりません。このような数を超越数と呼びます。

ただし今回の「有限桁では正確に保存できない」という議論には、π が無理数であることだけでも十分です。

Algebraic vs Transcendental

√2 : root of x2 - 2 = 0

π : root of no integer-coefficient polynomial

3.2 Symbolic Representation

記号として保存することはできる

厳密にいうと、コンピュータは文字列として π や sqrt(2) を保存できます。

数式処理システムであれば、π(√2 - 1) のような式を、式のまま保持することもできます。

  • 誤解しやすい表現：「π は一切コンピュータに保存できない」
  • より正確な表現：「π の完全な数値展開を、有限桁の数値として保存することはできない」

したがって数値計算では、π ≈ 3.14159265 のような有限桁の近似値を使います。

近似（Approximation）と精度（Precision）

有理数による近似

任意の無理数は、差をいくらでも小さくできる有理数によって近似可能です。

電卓の固定桁数表示のように、要求される誤差（エラー）を許容限界以下に抑え込みます。

入力誤差と出力誤差

コンピュータへの入力が近似値である以上、アルゴリズムの導く出力も近似値となります。

理想の解との差（精度）をコントロールできるかどうかが計算科学の要となります。

Approximation Error

5. Approximation Error

近似値と誤差

本当の値を a、コンピュータが持つ近似値を ã とします。

このとき、絶対誤差は Eabs = |a - ã| で定義されます。

例えば π ≈ 3.14 とした場合、Eabs = |π - 3.14| ≈ 0.00159265 です。

誤差が小さいほど、本当の値に近い計算になります。

Absolute Error Eabs = |a - ã| |π - 3.14| ≈ 0.00159265

What Does "Correct to n Digits" Mean?

5.1 「小数第 n 位まで正しい」とは

例えば、√2 = 1.41421356... を小数第2位まで四捨五入すると 1.41 です。

ただし計算中は真の値が見えないため、1つの近似値だけでは「本当に正しく丸められたか」を保証できません。

そこでヘロン法では、真の値を挟む2つの値（下限・上限）を作って判定します。

これは後で登場する停止条件に直結します。

14．ヘロン法の一般形

今度は、√2 ではなく、正の数 N の平方根を考えます。

求めたい値を r = √N とします。

  3. 二つの平均を次の候補にする
gk+1 = 1 2 ( gk + N gk )
gk+1 = gk + N gk 2

Method 1

方法1：上下の値を丸めて比較する

上側の候補を g、下側の候補を ℓ = Ng とします。

小数第 n 位まで求めたい場合、 round(g, n) と round(ℓ, n) を比較します。

方法2：区間の幅を調べる

区間の幅 g − Ng が十分小さくなったら停止する方法もあります。

ここで ε は許容する誤差です。

ただし、特定の小数桁へ正しく丸められたことを保証したい場合は、単に区間が狭いだけでなく、 上下の境界を丸めた結果が一致するかを確認する方が明確です。

17．一般化した擬似コード

非負の数 N の平方根を、小数第 n 位まで求める擬似コードは、次のように書けます。

Pseudocode
INPUT N, n

IF N < 0 THEN
    OUTPUT "実数の平方根は存在しない"
    STOP
END IF

IF N = 0 THEN
    OUTPUT 0
    STOP
END IF

g ← MAX(1, N)

LOOP
    lower ← N / g

    IF ROUND(g, n) = ROUND(lower, n) THEN
        OUTPUT ROUND(g, n)
        STOP
    END IF

    g ← (g + lower) / 2
END LOOP

ここで、

g

は上側の候補、

lower = N g

は下側の候補です。
