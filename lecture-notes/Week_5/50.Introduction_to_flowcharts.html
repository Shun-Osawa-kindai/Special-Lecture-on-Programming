Visualizing Logic

アルゴリズムをどう記述するか？
「図と文字でプロセスを描く」

アルゴリズムを人に伝えたり設計する際、自然言語の箇条書きやコードだけでは処理の流れが見えにくくなります。

フローチャート（Flowchart）は、図形と矢印を用いてあらゆるプロセスを抽象的かつ明快に記述できる標準的な手法です。

ソフトウェアの設計だけでなく、業務ワークフローやプロジェクト管理にもそのまま応用できます。

Everyday Process

Practical Example

日常の行動をフローチャートにする

「部屋に入って着席する」という日常の行動にも、判断とループ（繰り返し）が存在します。

  • 部屋に入る（開始）
  • 明るさを確認する（データ入力）
  • 「暗いか？」を判定（Yes / No 分岐）
  • 暗ければ電気をつけ、再度確認する（ループ）
  • 明るければ着席する（終了）

Standard Symbols 1

Flowchart Elements (1)

開始・終了と入出力の記号

楕円（Oval / Terminal）

フローチャートの開始（Start）と終了（Stop）を示します。

例：「部屋に入る」「着席する」「計算開始」

平行四辺形（Parallelogram）

データの入力（Input）と出力（Output）を示します。

例：「明るさを確認する」「整数xを入力」「解を出力」

Standard Symbols 2

Flowchart Elements (2)

基本処理と判断分岐の記号

長方形（Rectangle）

算術計算や代入などの基本処理（Action / Process）を示します。

例：「電気をつける」「平均を計算」「gを更新」

ひし形（Diamond / Decision）

条件による判断（Decision）を示し、Yes / No に分岐します。

矢印（Control Flow）とともにプログラムの構造を決定します。

ヘロンの解法をフローチャートで定義する

前回の平方根近似アルゴリズムを、汎用フローチャートに落とし込みます。

  • 目的： 整数 x の平方根 √x を小数第 n 位まで求める。
  • 入力（Input）： 整数 x と目標桁数 n
  • 推測値（Guess）： 初期候補 g（1 < g < x）
  • 出力（Output）： 精度を満たした推測値 g
Problem Formalization √x to n decimal places Input: x, n ➔ Output: g

反復更新（ループの継続）

x / g と g が小数第 n 位で一致しない場合：

新しい候補値 g = (x/g + g) / 2 を計算し、再び x / g の計算へとループバックします。

終了判定（目標精度の達成）

四捨五入して小数第 n 位まで両者が一致した瞬間：

ループを抜け、確定した g を解として出力してアルゴリズムを停止（Stop）します。

Summary

フローチャートがもたらす設計力

プロセスの可視化： 図と文字を組み合わせることで、複雑な条件分岐やループ構造を一目で把握できる。
標準記号の規律： 楕円（端子）、平行四辺形（I/O）、長方形（処理）、ひし形（判断）の明確な役割分担。
実装への橋渡し： フローチャートで論理を整理してからコーディングに入ることで、迷いなく堅牢なプログラムが書ける。
