Continuous vs Discrete

Discretisation

連続する世界を「離散的なステップ」へ

フローチャートは汎用的であり、例えば「望む温度になるまでサーモスタットを回し続ける」といった連続的（Continuous）なプロセスも記述できます。

しかし、コンピュータは連続的な指示を理解できません。
「0.5度ずつ温度を上げる」といった明確な離散的（Discrete）なステップへ分解する処理、すなわち「離散化（Discretisation）」が不可欠です。

Discretisation in Computing
The Assignment Symbol

Assignment

変数への値の格納：代入（Assignment）

離散的なステップを書き下す「擬似コード」において、最初に登場する重要な記号が代入記号（矢印）です。

x ← 2 は「変数 x に 2 という値を割り当てる」ことを意味します。
人間が読むための記法なので、細かい型の宣言などは省略できますが、論理的な一貫性は保つ必要があります。

x ← 2
変数 x に 値 2 を格納する
Assignment Operator
Self-Referential Update

Updating Variables

古い値を使って新しい値を更新する

擬似コードは上から下へ順番に処理されます。

代入記号の大きな特徴は、自己参照的（Self-referential）な更新ができる点です。現在の x の値を使って計算を行い、その結果で x 自身を上書きします。

x ← 2 Initial state: x is 2
x ← x + 1 Updated: x is 3
Self-Referential Assignment
Naming Conventions

Meaningful Names

変数には「意味のある名前」をつける

制約：スペースを含めない

変数名に x や t だけでなく、意味がわかる単語を使えますが、スペースを含めることはできません。

複数の単語をつなぐ作法

  • DesiredTemperature (PascalCase)
  • desiredTemperature (camelCase)
  • Desired_Temperature (snake_case)

Applied Example

Thermostat Control

実践：サーモスタットの温度制御

現在の温度（t）が、目標の温度（T）より低い場合、温度を 0.5度上昇させる離散的なステップを擬似コードで記述します。

t ← 18
T ← 20

if ( t < T ) then
  t ← t + 0.5
end if
