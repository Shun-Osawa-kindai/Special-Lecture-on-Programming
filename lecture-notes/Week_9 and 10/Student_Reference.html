@app.route(...)や@app.post(...)は、URLと要求方法を処理関数へ対応づけます。今回読む入口はadd_todo、search_todos、toggle_todoです。

入力の値を取り出す

title = request.form.get("title", "").strip()

POSTフォームのname="title"に対応します。見つからなければ空文字、stripで前後の空白を除きます。その後、空欄や120文字超を拒否します。フォームにあるcsrfは別の検証に使うため保持します。

database().execute(
    "INSERT INTO todos (user_id, title) VALUES (?, ?)",
    (g.user["id"], title)
)
database().commit()

SQLの?へ渡す値は、SQLの文字列とは分けます。g.userは今回の要求で確認されたユーザーです。登録成功後は302で登録画面へ戻ります。

検索の条件を読む

SELECT id, title, completed, created_at FROM todos
WHERE user_id = ? AND title LIKE ? ESCAPE '\'
ORDER BY id DESC LIMIT 100
部分このアプリでの役割
SELECT / FROMtodosの必要な列を読む
user_idログイン中のユーザーに属する行を選ぶ
LIKEタイトルの一部が検索語に合う行を選ぶ
ORDER BY / LIMIT新しいID順で、最大100件を表示する

queryはGETのqから取り出します。%や_などは、通常の文字として探すためescapedへ変換します。この処理を保ったまま、未完了の条件を一つ追加します。

現在値を変更する

UPDATE todos
SET completed = CASE WHEN completed = 1 THEN 0 ELSE 1 END
WHERE id = ? AND user_id = ?

対象のIDと所有者で一件を選び、完了状態を反転します。二度受け付けると元に戻ります。created_atは更新せず、変更履歴も記録しません。

確認問題

検索に出ないToDoは、削除されたと言えるでしょうか。

答えと確認方法

言えません。ユーザー、検索語、未完了条件、100件上限などで結果に出ない場合があります。自分の入力と検索条件を確かめ、必要なら読み取り専用の観察補助でDBの行を見ます。

構文を暗記することより、入力・処理・保存・表示の対応を指し示せることを目指します。
