演習09-A：表示する列を選ぶ

本の名前だけを表示してください。続いて、本の名前と価格を表示してください。

解答例と確認
SELECT name FROM book ORDER BY id;
SELECT name, price_pence FROM book ORDER BY id;

どちらも3行です。最初はnameの一列、次はnameとprice_penceの二列になります。表示する列を減らしても、元の表の列は消えません。

演習09-B：一冊を追加する

ID 4、名前「Testing book」、価格1800ペンスの本を追加してください。

解答例と確認
INSERT INTO book (id, name, price_pence)
VALUES (4, 'Testing book', 1800);

SELECT id, name, price_pence FROM book WHERE id = 4;

結果はID 4の一行です。全件を確認すると4行になります。同じINSERTを繰り返すとIDの重複で拒否されます。

条件と表示順

30ポンドより高い本を調べます。保存単位がペンスなので、条件には3000を使います。

SELECT name, price_pence
FROM book
WHERE price_pence > 3000
ORDER BY id;

結果はDatabase bookとExpress bookの2行です。次は価格の高い順に表示します。

SELECT id, name, price_pence
FROM book
ORDER BY price_pence DESC, id;

09-Bまで終えていれば、表示順はID 1、3、2、4です。検索結果の順番が変わっても、IDは変わりません。

第10回：一件の変更と確定

四冊から始める

第10回では別の練習用DBを使います。第9回の結果を残したまま、同じ開始状態を用意できます。

python lab.py start10
python lab.py open10

新しく作った data/book10.sqlite3 には、ID 1〜4の四冊が入っています。価格は順に4025、2500、3199、1800です。既存のDBがあれば保持します。

演習09-C：一件だけ更新する

ID 2の本の価格を2800ペンスに変更してください。実行前と実行後に、対象の行を確認してください。

解答例と確認
SELECT id, name, price_pence FROM book WHERE id = 2;

BEGIN;
UPDATE book SET price_pence = 2800 WHERE id = 2;
SELECT changes() AS changed_rows;
SELECT id, name, price_pence FROM book WHERE id = 2;
COMMIT;

SELECT id, name, price_pence FROM book ORDER BY id;

changed_rows は1です。ID 2の価格だけが2500から2800へ変わり、他の三冊の値はそのままです。COMMITで、この変更を確定します。

WHEREを外した場合を観察する

次は練習用DBで、確定せずに結果を観察する例です。何行が変わるかを予想してから実行します。

BEGIN;
UPDATE book SET price_pence = 0;
SELECT id, name, price_pence FROM book ORDER BY id;
ROLLBACK;

SELECT id, name, price_pence FROM book ORDER BY id;

最初のSELECTでは四冊すべての価格が0です。ROLLBACK後には、4025、2800、3199、1800へ戻ります。ID 2の2800は、先の演習09-Cで確定した値です。

ROLLBACKで戻せるのは、いま未確定のトランザクションです。すでにCOMMITした変更を、あとから同じROLLBACKで取り消すことはできません。

演習09-D：指定した行を削除する

ID 4の本を削除してください。削除対象と、削除後の表を確認してください。

解答例と確認
SELECT id, name, price_pence FROM book WHERE id = 4;

BEGIN;
DELETE FROM book WHERE id = 4;
SELECT changes() AS changed_rows;
COMMIT;

SELECT id, name, price_pence FROM book ORDER BY id;

changed_rows は1です。ID 1、2、3の三冊が残ります。DELETEはデータ行を削除する操作で、表の定義は残ります。

制約を確かめる

以下を一文ずつ実行し、受け付けられない理由を説明してください。

INSERT INTO book (id, name, price_pence)
VALUES (2, 'Another book', 1000);

INSERT INTO book (id, name, price_pence)
VALUES (5, NULL, 1000);

INSERT INTO book (id, name, price_pence)
VALUES (6, 'Negative price', -1);
理由と確認

順に、ID 2の重複、名前のNULL、負の価格が拒否されます。エラーメッセージの見え方は環境によって異なります。

SELECT id, name, price_pence FROM book ORDER BY id;

拒否された行は追加されません。ID 1、2、3の三冊、価格4025、2800、3199のままです。

初期状態への戻し方

現在開いているSQLコンソールを .quit で終了してから実行します。--reset は、その練習用book表の現在の記録を消して、開始状態に戻す明示的な操作です。

目的通常の端末で実行するコマンド結果
第9回を最初からpython lab.py start9 --resetbook9のbook表を0行に戻す
第10回を最初からpython lab.py start10 --resetbook10のbook表を四冊、ID 2=2500に戻す
第9回の続きをするpython lab.py open9同じbook9を開く。初期化しない
第10回の続きをするpython lab.py open10同じbook10を開く。初期化しない

start9 と start10 だけでは、すでにあるDBの記録は変えません。初期化してよいと判断した場合にだけ --reset を付けます。ほかの練習用DBやToDoアプリのDBは変更しません。

困ったとき

状況確認すること
DBがありませんと表示される案内された start9、start10 または checkpoint9 を先に実行する。open/showは新規DBを作らない。
...> が続くSQL末尾のセミコロンや、引用符の閉じ忘れを確認する。Control+Cで入力中のSQLを捨てられる。
IDの重複エラー同じINSERTを繰り返した可能性がある。SELECTで現在の行を確認する。
BEGINを実行できないすでにトランザクションを開始していないか確認する。意図した変更か確かめ、COMMITまたはROLLBACKで区切る。
開き直すと値が戻るBEGIN後の変更をCOMMITしたか確認する。未確定のまま.quitで終了すると、その変更は取り消す。
期待した行がない.databases でDBのパスを確認する。WHEREの条件と、自分が実行した演習の範囲を確認する。

この簡易コンソールは、授業で使うSQLと一部のドットコマンドに対応しています。完全なSQLite CLIと表示や対応コマンドは同一ではありません。.help で対応する操作を確認できます。
