Topic Orientation
Problem Formulation

Mathematical Model

問題の数理モデル化：変数と制約

変数の定義
  • N_0 : 兄弟が 0人 のゲスト数
  • N_1 : 兄弟が 1人 のゲスト数
  • N_2 : 兄弟が 2人 のゲスト数

目的（Goal）： N_0 + N_1 + N_2 を最大化する。

条件と制約（Constraints）

おもちゃとお菓子の配分から、プレゼントを受け取る総人数は 6人 と決まっています。

N_0 + 2*N_1 + 3*N_2 = 6

Problem Formulation
List Constraints

Applying the List

ゲストリストから上限値を設定する

与えられたゲストリストの構成に基づいて、それぞれのゲストタイプの上限（マックス人数）を m_0, m_1, m_2 として定義します。

  • m_0 = 2 （兄弟0人は最大2人まで）
  • m_1 = 3 （兄弟1人は最大3人まで）
  • m_2 = 1 （兄弟2人は最大1人まで）
List Constraints
Algorithm Implementation

Brute Force Approach

擬似コード：3重の for ループによる全探索

カウンタ変数 i, j, k を使って、0から上限 m までのすべての組み合わせ（Every possibility）を試行します。

総人数が 6 になる条件を満たし、かつ過去の最大ゲスト数 t を上回った場合のみ、t を更新します。

t ← 0
for 0 ≤ i ≤ m_0 do
  for 0 ≤ j ≤ m_1 do
    for 0 ≤ k ≤ m_2 do
      if i + 2*j + 3*k == 6 then
        if i + j + k > t then
          t ← i + j + k
        end if
      end if
    end for
  end for
end for
return t

Tracing the Algorithm

Execution Trace

アルゴリズムのトレースと最適解の発見

ループの推移（List 1）
  • (i,j,k) = (0,3,0) ➔ 総数6 ➔ ゲスト 3 人
  • (i,j,k) = (1,1,1) ➔ 総数6 ➔ ゲスト 3 人
  • (i,j,k) = (2,2,0) ➔ 総数6 ➔ ゲスト 4 人

➔ 最終出力（最大ゲスト数）: t = 4

リストが変わった場合（List 2）

もし m_0=3, m_1=1, m_2=2 と新しいリストが渡されても、同じ擬似コードを走らせるだけで自動的に答えが出ます。

(i,j,k) = (3,0,1) のとき総数6になり、結果としてやはり t = 4 が導き出されます。

Edge Cases

No Solutions

解が存在しないケース（Edge Cases）

アルゴリズムは常に答えを見つけるとは限りません。「条件を満たす組み合わせが存在しない」という事実を証明することもアルゴリズムの役割です。

極端なゲストリストの例

  • 兄弟 0人のゲストが 5人（m_0 = 5）
  • 兄弟 6人のゲストが 1人（大家族）
  • このリストをアルゴリズムに通すと、どう組み合わせても合計を「6」にすることができません。
  • 結果： ループ終了後、t は初期値の 0 のまま返されます（招待不能）。
