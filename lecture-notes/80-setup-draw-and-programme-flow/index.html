Program Structure

Execution & Structure

プログラムの実行と構造
（Program Flow）

プログラムがどのように上から下へと実行され、どのように画面の描画（フレーム）が繰り返されるのか、その基本構造を紐解きます。

Program Flow Slide 1 / 8
Code Blocks

Setup & Draw

2つの基本ブロック：setup() と draw()

setup() 関数

プログラムの開始時に一度だけ実行されます。キャンバスの作成などの初期設定を記述します。

draw() 関数

setup() 完了後、フレームごとに継続的（繰り返し）に呼び出されます。

Program Flow Slide 2 / 8
Execution Order

Order of Execution

プログラムの実行順序

コードは基本的に本のように「上から下へ」順番に実行されます。

  • 最初に setup() が走る
  • 次に draw() が繰り返し実行される
  • 順序を間違えると、意図しない見た目やエラーの原因になる
1.

setup() 実行

初期設定（1回のみ）

2.

draw() ループ

フレームごとの描画（連続）

Frames & Animation

Frames

「フレーム」とアニメーションの原理

映画やアニメーションと同じように、ブラウザも静止画（フレーム）を連続して描画することで動き（アニメーション）を表現しています。

draw() が1回呼び出されるたびに、新しい1フレームが画面に生成されます。

Program Flow Slide 4 / 8
Layering Rules

Paint Order

重なりのルール（ペイントの順序）

1つのフレーム内でも、コードが書かれた順序がそのまま描画の順序になります。

後から書いた（実行された）図形ほど、手前（上）に重なって描画されます。

Program Flow Slide 5 / 8
Alpha Channel

Alpha & Blending

アルファ値による色の組み合わせ

図形の色にアルファ値（透明度、例: 100）を加えると、下の層の色と混ざり合います。

色のブレンド例

青い正方形に半透明（100）を指定すると、下の赤い正方形と重なって「紫色」のように見えます。

fill(0, 0, 255, 100);
rect(150, 150, 100, 100);
Program Flow Slide 6 / 8
Unexpected Behavior

Debugging Flow

意図しない挙動を防ぐための注意点

描画順序のミス

背景を塗りつぶす background() コマンドを、図形を描いた「後」に置いてしまうと、図形が背景で隠されて消えてしまいます。

鉄則：background の位置

draw() 関数の冒頭で background() を呼び出し、毎フレームキャンバスをリフレッシュするのがアニメーション制作の基本です。

Program Flow Slide 7 / 8
Summary

Summary

プログラムの実行と構造のまとめ

プログラムがどのように実行され、どのような順序で画面に描画されるかを理解することで、複雑なアニメーションや表現をコントロールできるようになります。

今回の重要ポイント

  • setup() と draw()：初期化とループ描画の役割分担
  • 上から下への実行：コードの記述順がそのまま処理の順序
  • ペイントの順序：後から描いた図形が手前に重なる

「順序とループを制する者が、アニメーションを制す」
