Solar System Visualization

配列の実践：太陽系8惑星のモデリング
「データで宇宙を描く」

前回の講義で学んだ配列の基本構文を使って、太陽系の8つの惑星（水星・金星・地球・火星・木星・土星・天王星・海王星）を描く実践プロジェクトに挑みます。

天体ごとに異なる「大きさ（直径）」「名前（ラベル）」「色彩」の3つの要素を、それぞれ独立した3つの配列に格納して連動させます。

第1の配列：惑星の大きさを管理する sizes

まずは8つの惑星それぞれの直径（ピクセル値）を数値配列 sizes として定義します。

水星（最も小さい）から木星（最大）まで、天体のスケール比を反映した8個の数値を角括弧の中にカンマ区切りで並べます。

  • sizes[0] ➔ 水星のサイズ（微小なドット）
  • sizes[4] ➔ 木星のサイズ（巨大なガス惑星）
  • sizes[7] ➔ 海王星のサイズ（最後の8番目）

天体をキャンバスの中央に横並びにする

Y座標はすべて画面の垂直中央（height / 2）に固定し、X座標を左から順に広げて配置します。

木星や土星などの巨大惑星が重なり合わないよう、各天体の間隔を 125px 程度空けて並べていきます。

⚠️ インデックスの境界：
8個の惑星を描画するとき、最後の海王星は sizes[8] ではなく sizes[7] です！
ellipse(50, height / 2, sizes[0], sizes[0]);

ellipse(175, height / 2, sizes[1], sizes[1]);

ellipse(925, height / 2, sizes[7], sizes[7]);

2nd Array: Planet Names

String Array & Labels

第2の配列：天体ラベルを添える names

円が並んだだけではどの天体か分かりにくいため、文字列の配列 names を作成し、天体の真下にラベルを出力します。

各文字列要素はクォーテーションで囲みます。描画位置は惑星と同じX座標、Y座標は少し下（height / 2 + 100）に指定します。

sizes[0] と names[0] が同じ「水星（Mercury）」を指すように、インデックス番号によって異なる配列同士が1対1に対応します。
文字列配列とラベル描画
var names = [
  "Mercury", "Venus", "Earth", "Mars",
  "Jupiter", "Saturn", "Uranus", "Neptune"
];

fill(255); text(names[0], 50, height / 2 + 100);
text(names[1], 175, height / 2 + 100);

Color Names & Naming Tip

第3の配列：色彩を与える colours 配列

① p5.jsの「名前付きカラー」

p5.jsでは、RGBの数値だけでなく、ウェブ標準のカラー名文字列（"red", "green", "sienna", "cyan" など約250色）をそのまま fill() に渡して塗ることができます。

var colours = [
  "gray",   "brown",  "green",  "red",    "sienna", "gold",   "cyan",   "blue"    

② 命名のコツ：color vs colours

p5.jsには最初から color() という組込み関数が存在します。

変数名を color にするとシステムの機能と名前が衝突して不具合を起こすため、複数形にするか、あえてイギリス英語の colours（uを入れる）と命名して回避するのがプロの知恵です。

State Pollution Trap

Color Reset

文字まで染まる「描画ステート持ち越し」の罠

⚠️ 発生する問題

fill(colours[0]); で惑星を塗ったあと、そのまま text(names[0], ...) を呼ぶと、テキストの文字色まで惑星の濃い色に染まってしまい、背景に沈んで読めなくなります。

fill(colours[0]);
ellipse(50, height / 2, sizes[0], sizes[0]);
text(names[0], 50, height / 2 + 100);

💡 解決策：文字描画の直前で白に戻す

テキストを描く直前に、必ず明示的に fill(255);（白色）を挟むことで、くっきり読みやすいラベルを保ちます。

fill(colours[0]);
ellipse(50, height / 2, sizes[0], sizes[0]);

fill(255);
text(names[0], 50, height / 2 + 100);

Code Repetition Paradox

Code Repetition Paradox

「同じ処理を8回もコピペする」違和感の正体

完成したコードを眺めると、ある強烈な疑問が湧き上がってきます。

「インデックス番号が 0 から 7 へ 1 ずつ増えているだけで、全く同じ命令を8回も手書きしているのは非効率ではないか？」

もし太陽系外惑星が100個、1,000個あったら、このコードは破綻してしまいます。この「退屈で冗長なコピペ」を根滅するために生まれたのが、前週に学んだ for ループ です！

Summary & Next Evolution

配列を自在に操る「次の進化」へ

数値・文字列・カラーという異なる型の配列を連携させ、リアルな天体モデルを構築できました。
