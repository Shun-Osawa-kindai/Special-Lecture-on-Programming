配列とforループの落とし穴
「よくあるバグとその回避策」

本トピックでは、プログラミングにおける2大重要概念である「配列（Arrays）」と「forループ（for loops）」を学びました。

非常に強力な道具である一方、初心者のみならず熟練プログラマーでさえ一度はハマる「典型的な構文ミス・論理エラー」が存在します。

エラーが出たときに冷静に原因を突き止められるよう、代表的なトラブル事例とデバッグの鉄則を確認しましょう。

Common Pitfalls & Bugs
Array Pitfall 01

Bracket Syntax Confusion

配列の宣言で「波括弧 {}」を使ってしまう

配列を定義するときは必ず角括弧（Square Brackets）[] を使用します。

しかし、誤ってオブジェクト用の波括弧（Curly Brackets）{} を書いてしまい、カンマで値を並べると、コンソールに次のエラーが発生します。

エラー表示例:
SyntaxError: Unexpected token ','

JavaScriptは {} を見ると「オブジェクト（キーと値のペア）」が来ると解釈するため、いきなり , が現れたことで構文エラーを出します。

誤りと修正の対比
var myArray = {1, 2, 3};
// => Unexpected token ',' エラー！

var myArray = [1, 2, 3];
// => 正常に配列として認識される

Array Pitfall 02

Trailing Comma & Undefined

末尾にカンマを置くと「見えない要素」ができる

エラーが出ない「サイレントバグ」

配列の最後の要素の直後に、誤って余分なカンマ（,）を残してしまうケースです。

var items = [10, 20, 30, ];
JavaScriptは構文エラー（赤文字）を出さないため一見動いているように見えます。しかし、実行環境によっては末尾に未定義の空要素（undefined）が作られたり、length が想定と食い違う原因になります。

対策：末尾のカンマは必ず閉じる直前に消す

最後の値の後ろにはカンマを置かず、直接閉じ角括弧 ] を書くのが安全で美しい作法です。

var items = [10, 20, 30];
console.log(items.length); 余計なカンマを排除して、常に意図通りの要素数・インデックス境界を保ちましょう。

For Loop Pitfall 01

Missing Afterthought

後処理 i++ を忘れると「無限ループ」に突入する

for ループの3つの要素（初期化・継続条件・後処理）のうち、最後の後処理（i++ や i += 1）を書き忘れるのは極めて多いミスです。

何が起きるのか？
カウンタ i の値が 0 のまま一度も増えません。
そのため条件式 i < 40 は永遠に true のまま成立し続け、プログラムが一生ループを抜け出せなくなります。
致命的な無限ループの例
for (var i = 0; i < 40; ) {
  console.log(i);
  // => 永久に 0 を出力し続けブラウザがフリーズ！

System Freeze Warning

Infinite Loop Impact

ブラウザが固まり、PCのファンが唸り声をあげる

発生する現象

無限ループに陥ると、CPU使用率が一瞬で100%近くまで跳ね上がり、パソコンのファンが激しく回転し始めます。

ブラウザの画面は完全にフリーズし、クリックしてもリロードしても一切反応しなくなります（クラッシュ状態）。

脱出と復旧の手順

  • 1. タブを強制終了： ブラウザの応答不能タブを強制的に閉じます。
  • 2. コードを修正： エディタ側で i++ を確実に書き足します。
  • 3. 再度開く： 修正後にブラウザでプレビューを開き直します。

※ベテランでもうっかり起こす事故です。焦らずタブを閉じて対処しましょう。

For Loop Pitfall 02

Reversed Condition Bug

不等号の向きを逆にすると「1回も動かない」

条件式で <（小なり）と書くべきところを、うっかり >（大なり） と書いてしまうミスです。

なぜ何も起きないのか？
ループの開始時、初期値は i = 0 です。
最初の1回目を実行する前の判定で 0 > 40 をテストしますが、これは最初から false（偽） です。
したがって、ループ本体の処理は1回も実行されずに即座にスキップされます。
実行されない不発コード
for (var i = 0; i > 40; i++) {
  console.log(i);

Scope & Declaration

Counter Declaration

カウンタ変数の先頭には必ず var をつける

var を省略した場合の危険性

for (i = 0; ...) のように var を付けずに書くと、JavaScriptは変数 i を勝手にグローバル変数（プログラム全体で共有される変数）として登録してしまいます。

for (i = 0; i < 10; i++) { ... }

意図しない値の衝突事故を防ぐ

他の場所や別のループでも同じ名前 i を使っていた場合、変数の値が互いに上書きし合ってループ回数が狂う凶悪なバグを引き起こします。

for (var i = 0; i < 10; i++) { ... }

短いコードであっても、常に var i = 0 と宣言する習慣を守りましょう。

トラブルシューティング・チェックリスト

  • 配列の括弧： 波括弧 {} ではなく角括弧 [] を使っているか
  • 末尾カンマ： 最後の要素の後ろに余計な , を残していないか
  • 後処理： ループの最後に i++ を書き忘れていないか
  • 不等号： i < 40 の向きが逆になっていないか
  • 変数宣言： カウンタの前に var を明記しているか
