配列走査と二重ループの落とし穴
「境界の逸脱と無限ループの回避」

配列のデータを順番に読み取る「データ走査（Traversal）」や、グリッドを描く「二重forループ」では、初学者が必ず直面する特有のエラーが存在します。

配列外へのアクセスによる undefined エラー、変数の書き換え忘れによるブラウザフリーズ、そしてカッコの対応ズレまで、原因の究明法と安全な実装パターンを学びます。

Traversal Pitfall 01

Out of Bounds

クリックで色を変える処理で起きる突然のエラー

クリックのたびに currentIndex++ して配列 colours の色を切り替えるプログラムを考えます。

エラーの発生：
最後の色（cyan等）を過ぎた瞬間にプログラムが停止し、コンソールに次のエラーが出力されます。
Uncaught Error: ... is not a valid color

➔ 存在しないインデックスへアクセスしたため、値が undefined に化けてしまいました。

var colours = ["red", "green", "blue", "yellow", "purple", "cyan"];
var currentIndex = 0;

function draw() {
  fill(colours[currentIndex]); rect(100, 100, 200, 200);
}

function mousePressed() {
  currentIndex++; // 限界を超えて増加し続ける
}

Boundary Logic

Index vs. Length

colours.length と length - 1 の決定的な違い

失敗例：length で直接リセット判定

要素が6個ある配列のインデックスは 0, 1, 2, 3, 4, 5 です。

if (currentIndex == colours.length) {
  currentIndex = 0;
}

currentIndex が 6 に到達したフレームで描画（draw）が先に走り、未定義エラーでクラッシュしてしまいます。

成功例：末尾インデックス（length - 1）で判定

最後の有効要素 length - 1（インデックス 5）に達した瞬間に、次のクリックで 0 へ巻き戻します。

if (currentIndex == colours.length - 1) {
  currentIndex = 0;
} else {
  currentIndex++;
}

Modulo Reset Technique

Cyclic Traversal

モジュロ演算子（%）による美しい循環制御

if / else の条件判定を使わずに、余りを求めるモジュロ演算子（%）を使うと、たった1行で完璧なループバックを実現できます。

  • (currentIndex + 1) % colours.length
  • 0 ➔ 1 ➔ 2 ➔ 3 ➔ 4 ➔ 5 と進み、6で割った余りは再び 0 に戻る
  • 配列の要素数が増減してもコードを書き換える必要がない
モジュロによる循環
let currentIndex = 0;
const colours = ["赤", "青", "黄", "緑", "紫", "橙"]; // 長さは 6

function mousePressed() {
  // 現在の色を表示（初回クリックは先頭要素）
  console.log(colours[currentIndex]);
  // 1行で配列末尾から先頭へ自動ループ
  currentIndex = (currentIndex + 1) % colours.length;
}

Nested Loop Pitfall 01

Variable Collision

コピペ時に起きる「i から j への変更漏れ」

外側のループ（行: i）をコピーして内側のループ（列: j）を作るとき、3つの構成要素のうち1つだけ書き換えを忘れてしまう事故が頻発します。

危険な記述パターン：
for (var j = 0; j < height; i++)
➔ j を進めるはずが、外側のカウンタ i を増やしてしまっている！
for (var i = 0; i < width; i++) {
  for (var j = 0; j < height; i++) { rect(i * cellWidth, j * cellHeight, cellWidth, cellHeight);
  }
}
// => j は永遠に 0 のまま増えず無限ループに！

Freeze & Hardware Crash

Browser Freezing

ファンが唸り声をあげ、インスペクタすら開けない

なぜブラウザが完全停止するのか？

JavaScriptはシングルスレッドで動作するため、無限ループに入るとCPUを100%占有してしまいます。

画面の描画更新はもちろん、F12キーや右クリックによる開発者ツール（デベロッパーツール）の起動すら一切受け付けなくなります。

安全な対処プロトコル

  • 1. タブを強制終了： ブラウザのタスクマネージャ等で該当タブを閉じる。
  • 2. エディタを確認： 内側ループの変数（初期化・条件・後処理）がすべて j に統一されているか凝視する。

Matching Braces

波括弧 {} の閉じ忘れとインデント（字下げ）

ループの中にループを入れると、末尾に波括弧が }} と2つ連続して並びます。

どちらか片方を閉じ忘れると、コードが長くなったときに「どの関数がどこで終わっているのか」見失い、原因不明のエラーに何時間も悩まされることになります。

対策： 内側のループを書くときは必ず「1段深くインデント」を揃え、対応するペアを目視できるように整頓しましょう。
for (var i = 0; i < width; i += cellWidth) {  for (var j = 0; j < height; j += cellHeight) { rect(i, j, cellWidth, cellHeight);
  }

Summary & Checkpoints

Summary & Checkpoints

トラブルを未然に防ぐマスターの作法

配列走査とネストループのエラーは、仕組みさえ理解していれば恐れることはありません。

トラブルシューティング・チェックリスト

  • 配列の末尾： 最後のインデックスは length - 1 であるか
  • リセット処理： モジュロ (index + 1) % length で循環させる
  • 変数の統一： 内側ループの初期化・条件・後処理すべてが j になっているか
  • 括弧の対応： ループの閉じ括弧 } がネストの深さ分揃っているか

ゲームプロジェクトや今後の制作で予期せぬ挙動に出会ったら、まずはインデックス境界とループ変数を疑ってみましょう！
