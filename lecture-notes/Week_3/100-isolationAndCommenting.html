ブラウザが何もエラーを出してくれないとき、私たちはどうやってバグを追い詰めればよいでしょうか？

文法は合っているのに期待通り動かない「論理エラー（Logic Error）」の解明、そして「他人のコード」や「久しぶりに開いた自分のコード」を読み解く強力な作法を学びます。

Logic Error vs Syntax Error

Silent Bugs

コンソールが黙ってしまうとき

例：壊れたロケットプログラム

  • W キーで上昇、A/D で左右移動する。
  • キーを離すと地表へ降下するはずが、降りてこない。
  • しかし、コンソールには赤文字のエラーが1行も出ない。

赤文字が出ないのは、書き方の間違い（構文エラー）ではなく、計算や条件の筋道が間違っている「論理エラー」だからです。

第一歩：コメントを入れて構造を把握する
他人のコードにコメントが皆無なら、自分で読み解きながら「ここは何をするブロックか」注釈を書き加えていきます。

Isolation Technique

Code Isolation

「コメントアウト」による描画の切り分け

どのブロックが画面のどの要素を描いているか不明な時は、コードの一部を一時的に無効化（コメント化）して画面の変化を観察します。

一括コメントアウトのショートカット

Mac: Cmd + /  |  Win: Ctrl + /

選択範囲を瞬時にコメント化／解除できます。

切り分けの例
// ロケット本体を描画する処理
// beginShape();
// vertex(x, y); ...
// endShape(CLOSE);
➔ 消えたパーツを確認して役割を特定！

Nondestructive Fixing

Safe Refactoring

非破壊的な修正（Safe Testing）

怪しいコードを見つけても、いきなり削除してはいけません。元のコードをコメントとして残し、新コードと並記してテストするのが安全な作法です。

バグ①：スコープ事故（`setup` 内での再宣言）

// var baseline = height - 80; // ← 誤り：ローカル変数で再宣言していた
baseline = height - 80;

バグ②：不等号の向き（条件判定ミス）

else if (rocket.y < baseline) { rocket.y += 1; } Commenting and Isolation Slide 4 / 5
Summary

Key Takeaways

コメント化と切り分けがもたらす価値

1. 非破壊的な変更：
旧コードを残してテストすれば、問題が起きた際にいつでも元の状態へ安全に戻せます。
2. マインドセットの復元：
処理ブロックにコメントをつけながら切り分けることで、作者の思考回路を追体験できます。
3. ゲームプロジェクトへの応用：
今後作成する大型のゲーム課題でも、この「パーツ切り分け」と「非破壊テスト」が最大の武器になります。
