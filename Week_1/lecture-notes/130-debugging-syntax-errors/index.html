プログラミングにつきものの「バグ（Bug）」。その言葉の由来は、コンピュータのパイオニアであるグレース・ホッパーが記録した1匹の蛾に由来します。

The First Bug

Core Skill

デバッグ（Debugging）という核スキル

間違いを直すプロセスを「デバッグ」と呼びます。プログラミングにおいて、エラーの原因を見つけ出して修正するスキルは、マスターするのに時間がかかる最も重要な能力の一つです。

  • エラーを恐れないこと
  • コンソールを手がかりに推理すること
  • 繰り返しを通じて直感を養うこと
Debugging Core Skill

Types of Errors

2種類の主要なエラー

1. 構文エラー (Syntax Error)

書き方のルール違反です。タイプミス、閉じ忘れたカッコ、カンマの抜けなど、プログラム言語の文法ミスを指します。

2. 引数エラー (Argument Error)

必要な情報（引数）の数が足りない、あるいは型が違うなど、関数やコマンドの使い方の間違いを指します。

コードを書いたのに真っ白な画面になる場合、コンソールを確認すると行番号付きのエラーが表示されます。

missing bracket after argument list 引数のリストの後にカッコが足りません（例：行11）。

Syntax Error 02

構文エラー②：コメントの付け忘れ

メモ書きのつもりで普通の文章を書いたままにしておくと、コンピュータはそれをコードとして解釈してしまいエラーになります。

SyntaxError: Unexpected identifier 想定外の識別子が見つかりました（例：行20）。

// overlapping shapes

Syntax Error 03

構文エラー③：大文字・小文字のスペルミス

p5.jsの命令（createCanvasなど）で大文字・小文字を間違えると、システムは関数を見つけられません。

ReferenceError: createcanvas is not defined 「定義されていません」という意味のエラー。
createcanvas(400, 400);

createCanvas(400, 400);
Syntax Error 03

Syntax Error 04

構文エラー④：カンマの抜けと推理

コンソールが指し示すエラー行が、必ずしも真の原因箇所とは限りません。コンソールの限界を知り、自らの推理力を働かせます。

コンソールの限界 「カッコの抜け」と指摘されても、実際は「カンマの抜け」である場合があります。
rect(100, 100 200, 200);
// ➔ 間にカンマを補うことで解決
Syntax Error 04

Argument Error 01

引数エラー①：情報の不足（足りない引数）

赤文字のエラーが出ない「サイレント・バグ」の代表例です。命令が必要としている情報の数が足りていない状態を指します。

  • rect() は4つの情報（x, y, width, height）が必要です。
  • 3つしか与えないと、一部の図形が描画されなくなります。
rect(100, 100, 200);
rect(100, 100, 200, 200);
Argument Error 01

Argument Error 02

引数エラー②：型の間違い（文字列の混入）

数値を期待している場所に、誤ってダブルクォーテーションで囲んだ「テキスト（文字列）」を入れてしまうミスです。

想定外の巨大化や描画崩れ 図形が消えたり、おかしなサイズに化ける原因になります。クォーテーションを外して数値を渡すことで解決します。
ellipse("200", "200", 50, 50);

ellipse(200, 200, 50, 50);

Summary

デバッグの第一歩を踏み出そう

バグやエラーの種類を知ることで、トラブルに直面しても冷静に対処できるようになります。
コンソールを頼りに、コードの謎を解き明かしていきましょう。

チェックリスト

  • コンソールを開いてエラー行を確認する
  • 構文エラー（カッコ、カンマ、スペル）を疑う
  • 引数エラー（数値の数や型）を確認する
